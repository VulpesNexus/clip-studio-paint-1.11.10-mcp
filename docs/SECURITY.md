# 安全模型

## 允许范围

- stdio，本地进程；不监听 TCP 端口。
- 仅固定路径 `CLIPStudioPaint.exe`。
- 每次控制前验证 Authenticode、CELSYS 公司字段、当前 profile 固定的文件版本（5.1.2.0 或 1.11.10.0）和当前 SHA-256。
- 严格 profile：默认接受任意 Windows 区域设置（`expected_locale: "*"`），也可固定指定区域设置；CSP 窗口 DPI 必须与 profile 一致（5.1.2 为 120，1.11.10 为 96）。
- 鼠标坐标是 CSP 窗口或客户区的 `0..1` 归一化值，并绑定 30 秒内截图。
- 屏幕截图前枚举 CSP 之上的全部顶层窗口；任何外部窗口与截图矩形相交都会拒绝，另保留 7×7 点校验作为二次检查。
- 接受路径参数的文件工具仅限本机配置定义的 `Input`、`Working` 和 `Exports` 三个独立根；通用自绘界面输入不具备路径语义证明。公开仓库不提供任何用户机器路径作为默认值。
- 路径会逐级检查配置根到目标之间的重解析点，并用 Windows 文件句柄回读现有目标的最终路径；硬链接数量只对已经存在的输入文件和替换目标检查。这些检查只能缩小、不能消除检查到使用之间的替换窗口。
- 所有输入串行；近期真人输入和按住的键会阻止执行。
- 10 个原子输入工具（点击、移动、拖动、滚动、文字、导航键、登记命令、Auto Action、命令序列和原生文件对话框）都需要 45 秒、单次使用、完整参数绑定的确认令牌。普通界面令牌只能配合批准后创建的新截图。`csp_cancel` 是受限例外：仍由宿主按 `writes` 审批，只向精确 CSP 主窗口或唯一标准对话框发送一次 `Escape`。
- 不注册 `Ctrl+S`：当前 CSP 文档路径无法从公开接口验证；保存和导出必须经路径校验后的原生文件对话框流程。
- 拒绝被登记为文件读写副作用或未声明 `attested_no_file_io` 的 Auto Action；服务不解析 `.laf`，无法证明管理员声明的真实性。
- Auto Action 快捷键仅允许 `Ctrl+Alt+[Shift]+F1..F12`；生产命令 ID、组合键、风险和副作用必须与固定 profile 完全一致。

## 明确拒绝

- 任意 Shell、PowerShell、进程、注册表或全盘文件工具。
- DLL 注入、程序补丁、Companion 私有协议和 `.lipcommand`。
- 解析或修改 `.clip` 二进制。
- 不提供账号、商店、购买、素材上传、云同步、社区与发布的语义工具，也禁止代理用通用点击/文本工具触达这些功能。
- 从 MCP 传入任意快捷键；只能调用版本化命令或管理员登记的 Auto Action。
- 向全系统释放修饰键/鼠标键的能力只用于服务器内部异常清理，不公开为 MCP 工具。
- UNC、设备路径、ADS、通配符、保留设备名、junction、symlink 和隐式覆盖。

## 仍然存在的风险

CSP 的主界面是自绘界面，Windows UIA 看不到图层、画笔和菜单对象。因此截图验证只能确认“可见像素发生了什么”，不能证明语义状态。坐标点击理论上可能点到错误的可见按钮；每次调用都必须先查看有效截图。

MCP 协议不会给服务端提供可加密验证的“用户已在 Codex 批准”证明；服务只能强制客户端先调用 preflight。授权模型因此信任 Codex 及其当前配置，不能抵御同一用户自行编写的恶意 stdio 客户端。若要覆盖该威胁，必须另加服务端自有确认 UI 或宿主签名声明，当前标准 MCP 没有这项能力。

因为自绘界面没有可机器识别的控件语义，服务端无法从坐标本身证明它不是账号、云端或发布入口。这里依赖四层约束：只控制 PAINT 而非启动器、服务器 instructions 明确禁止、截图/真人输入失效保护，以及每次由 `csp_preflight` 人工批准精确工具名和完整参数。为避免批准界面使 captureId 必然失效，注册配置自动批准 10 个服务端令牌门控的原子工具；它们没有匹配令牌就会拒绝。若需要硬隔离，应禁用全部通用坐标/文字工具，只启用登记命令和人工验证的 Auto Actions。

批准界面会关闭 CSP 的瞬态菜单，所以“先展开菜单、再批准坐标点击菜单项”不能安全支持；批准后的新截图若不再显示原目标，必须丢弃令牌。此类功能应改用登记命令或 Auto Action。

路径白名单对 `csp_open_document`、路径检查、资产枚举、导出监测和原生文件对话框等路径参数型工具是验证边界；句柄最终路径回读和硬链接检查缩小但不能消除检查到使用竞态。对通用坐标点击与文本输入只能是策略边界：它们理论上仍能手工打开菜单并输入任意路径，因此即使精确参数已获批准，也不得用于打开/保存/导出。服务端默认命令表刻意不提供无法绑定路径的 `Ctrl+S`。

原生文件对话框必须同时匹配 `#32770`、Shell 文件视图、文件名 Edit 控件 ID 和 `IDOK` 按钮，并用有超时的消息写入后回读精确路径。提交后若仍有覆盖/格式等对话框，MCP 不会自动点击；响应要求人工处理，文件仍须由 `csp_wait_for_file` 验收。

`GetLastInputInfo` 不能可靠区分真人与合成输入。本项目不猜测事件归属，而是把任何输入时间变化都视为授权失效，并检查全部按下的虚拟键；长拖动期间仍无法获得与原生输入驱动相同的完全隔离。不要在真人同时操作 CSP 时运行自动化。

安装与注册脚本会审计项目树、配置的素材根及其祖先 ACL，并拒绝自动递归修改 ACL。已验证参考部署曾发现上级目录向广泛主体授予写入权限，因此父级删除/替换权限应视为真实的本地多用户风险，而不是理论检查。脚本在发现不受信任的祖先时默认拒绝；显式风险开关只表示接受残余风险，并不会修复它。收紧祖先 ACL 可能影响仓库范围之外的数据，必须由机器管理员单独决定。公开仓库不假设任何盘符或用户目录天然可信。

依赖使用带 SHA-256 的 `requirements.lock.txt` 和 `pip --require-hashes` 安装。CSP 每次控制前重新验证签名、版本和固定哈希；这降低但不能消除同卷父目录被恶意替换的竞态。

## 本地分支：文件对话框语言验证

文件对话框的语言独立于 Windows 区域设置验证。目前支持法语、英语和简体中文的“打开”及“保存/导出”标签。标题和按钮必须在标准化后保持一致，并符合既有控件 ID 结构。未知或歧义对话框仍会被拒绝。可执行文件、DPI、快捷键、路径、窗口归属和预检检查保持不变。
